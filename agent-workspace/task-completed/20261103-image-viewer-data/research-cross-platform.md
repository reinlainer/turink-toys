# Windows·Linux 이미지 뷰어 UX 조사 (보기 전용 뷰어 설계 참고)

조사일 2026-11-03. 대상은 UX(조작감, 창 동작, 탐색 방식)이며 기능·기술은 제외한다.
표기: `[확인]` 공식 문서·소스 코드·글에서 직접 확인, `[2차]` 검색 요약이나 위키·블로그를 통한 간접 확인, `[미확인]` 근거를 찾지 못함.
조사의 한계: 클리앙·루리웹·에토랜드 등 한국 글은 일부만 열렸고(브런치·나무위키·더위키·반디캠 게시판은 403), 뽐뿌·디시·네이버 블로그는 본문을 읽지 못했다. Reddit은 검색에 거의 잡히지 않아 해외 의견은 리뷰 사이트와 포럼 위주다.

### 2-2. 앱별 상세

#### 꿀뷰 (반디소프트)

- 공식 단축키: [꿀뷰 단축키 목록](https://en.bandisoft.com/honeyview/help/shortcut/) `[확인]`
- 이웃 사진: 다음 = PgDn, 방향키, Space, 숫자패드 0. 이전 = PgUp, 방향키, Backspace, Shift+Space. 처음·끝 = Home·End. 10장 점프 = Ctrl+PgDn. 다음·이전 폴더·압축 파일 = `]` `[`.
- 보기 모드: 9·1 = 창에 맞춤, 8 = 너비 맞춤, 0 = 원본 100%, Z = 작은 사진 늘리기, 6·7 = 스마트 두 장 보기. 확대 중 숫자패드로 방향 이동. `/` = 확대 시 미리보기 창 표시.
- 창: M = 최대화·복원, N·F11·Alt+Enter = 전체화면, Q = 최소화, Ctrl+A = 항상 위, Shift+F5 = 테두리 표시·숨김.
- 창 크기를 키보드로 바꾸는 기능은 없다. 개발사가 "Windows 키 + 화살표로 창을 화면에 맞추라"고 답함: [구글 그룹 질의](https://groups.google.com/g/honeyview-win/c/32Bov3_1uus) `[확인]`
- 사진마다 창이 커졌다 작아지는 현상은 환경설정 > 기타의 "이미지 크기에 맞춰 창 크기 조절"을 끄면 사라진다. 우클릭 메뉴 보기 모드의 "꽉차게 보기"·"작은 그림도 꽉차게 보기"도 영향을 준다: [에토랜드 질답](https://etoland.co.kr/b/com/view/%EA%BF%80%EB%B7%B0%EA%B0%80-%EC%82%AC%EC%A7%84%EC%9D%98-%ED%81%AC%EA%B8%B0%EC%97%90-%EB%94%B0%EB%9D%BC%EC%84%9C-%EC%BB%A4%EC%A1%8C%EB%8B%A4-%EC%9E%91%EC%95%84%EC%A1%8C%EB%8B%A4-%EC%95%88%ED%95%98%EA%B2%8C-337821) `[확인]` (기본값이 켜짐인지는 글에 명시되지 않음: 질문자가 "계속 바뀐다"고 했으므로 기본 켜짐으로 추정, `[미확인]`)
- 압축 파일: ZIP, RAR, 7Z, LZH, TAR, CBR, CBZ를 풀지 않고 열람: [반디소프트 한국어 소개](https://kr.bandisoft.com/honeyview/) `[확인]`
- 파일 관리: 삭제(Delete), 영구 삭제(Shift+Delete), 사진 폴더로 복사·이동, 탐색기에서 보기(Ctrl+Enter) `[확인]`
- 현황: 업데이트 종료, 후속은 반디뷰 `[확인]`. 최종 버전 5.53(2024-06-21 종료)은 나무위키 요약 기준 `[2차]`.

#### 알씨 (이스트소프트)

- 한국어 비교 글은 "폴더에 사진이 많으면 느리고 버전이 오를수록 무거워지며, 알툴즈 설치 권유와 업데이트 알림이 잦다"고 평가: [정원딸린집을 꿈꾸며](https://www.omdroid.com/266) `[2차]`
- 위키 요약은 "기능이 많아 무겁고 이미지 로딩에 시간이 걸린다. 일괄 편집만 알씨로 하고 뷰어는 따로 쓰는 사람이 있다"고 함: [더위키 알씨](https://thewiki.kr/w/알씨) `[2차]`
- 휠·창 동작 등 구체 조작은 확인하지 못함 `[미확인]`

#### ImageGlass

- 기능 목록: [공식 features](https://imageglass.org/docs/features) `[확인]`. 커서 위치 기준 확대, 확대 속도·이동 속도 조절, 폴더 주변 사진 미리 읽기(캐시), 클립보드 붙여넣기로 열기.
- 기본 설정(소스 코드): [Config.cs](https://github.com/d2phap/ImageGlass/blob/develop/source/ImageGlass.Lib/Settings/Config.cs) `[확인]`. 확대 모드 자동, 창 맞춤 꺼짐, 툴바·썸네일은 전체화면에서 숨김, 순환 탐색 켜짐, 썸네일 열 3개. 휠 기본값은 코드에서 비어 있어 확인하지 못했다. 설정 문서 미러 간에도 서로 다르게 적혀 있다 `[미확인]`.
- 탐색 모드: Turbo(다음 사진을 기다리지 않음)와 Sequential(한 장씩 기다림): [설정 문서](https://imageglass.org/docs/app-configs) `[확인]`
- 평가: 폴더를 넘길 때 Microsoft Photos와 달리 미리보기 생성 때문에 멈추지 않는다고 함. 단점은 파일이 많은 폴더에서 느림, 캐시를 올리면 메모리 증가: [WidsMob 리뷰](https://ko.widsmob.com/view-image/imageglass.html) `[2차]`
- 2025~2026 한국어 글에서는 꿀뷰의 대안으로 "가장 활발히 업데이트되지만 대안 중 가장 무겁다"는 평이 반복: [zod.kr 후기(검색 요약)](https://zod.kr/general/3478033) `[2차]`

#### FastStone Image Viewer

- 공식 기능 설명: [FSViewerDetail](https://www.faststone.org/FSViewerDetail.htm) `[확인]`
- 인상적인 부분은 전체화면의 "네 가장자리 팝업": 왼쪽 빠른 크기 조절, 아래 스크롤 내비게이터, 위 회전 버튼, 썸네일 줄 아래 폴더 트리. 커서 자동 숨김.
- 클릭 한 번으로 "화면 맞춤↔실제 크기" 전환, 누르고 있으면 돋보기, 한 번 더 클릭하면 맞춤으로 복귀.
- 가운데 클릭으로 브라우저 모드와 전체화면을 오감. 마지막으로 본 파일 기억, "다음 폴더로 자동 이동", Alt+좌우로 인접 폴더 이동.
- 사진 고르기: Q 태그, 별점 1~5, 태그된 것만 걸러 복사·이동·슬라이드쇼. 전체화면에서 `\` 키로 태그.
- 불만: 전체화면에서 순서가 뒤섞여 보이는 경우(브라우저에서 정렬 후 진입해야 함): [TechSpot](https://www.techspot.com/downloads/1845-faststone-image-viewer.html) `[2차]`. 한국 글은 "기능이 많아 다소 무겁고 파일 많은 폴더에서 썸네일 로딩이 느리다": [omdroid](https://www.omdroid.com/266) `[2차]`. 클리앙 맥 앱 질문 댓글은 "열 때마다 뜨는 팝업이 불편"이라고 함: [클리앙](https://www.clien.net/service/board/cm_mac/16321244) `[확인]`
- 해외 이용자는 "IrfanView보다 마우스만으로 탐색하기 쉽다", 단점은 "마우스를 누르고 있어야만 확대되는 점": [검색 요약, FileForum·DPReview 인용] `[2차]`

#### IrfanView

- FAQ: [irfanview.com/faq](https://www.irfanview.com/faq.htm) `[확인]`
- 창 맞춤: 표시 옵션에서 "창에 맞춤"을 고르고 "창 크기·위치 기억"을 켜면 창이 고정됨. "데스크톱에 맞춤" 계열은 창을 좌상단으로 옮기고 화면을 덮을 수 있어 주의가 필요함.
- 전체화면에서 큰 사진을 확대해 이동하려면 "다음 사진으로 넘어가기" 옵션이 걸림돌이 될 수 있음. 즉 "방향키가 이동인가 넘기기인가"가 설정 충돌의 지점.
- 휠 기본값, 확대 기억은 문서로 확인하지 못함 `[미확인]`. 인상은 "작고 빠르다(약 6MB)"뿐.

#### nomacs

- 공식 소개: [nomacs.org](https://nomacs.org/) `[확인]`. 핵심은 "여러 창의 확대·이동을 동기화해 두 사진 비교", 썸네일, 프레임 없는 모드.
- 한 리뷰는 "UI가 단순·빠르고 메타데이터·히스토그램 패널을 토글"한다고 평가하나 "더 이상 관리되지 않는다"고 적음(공식 소개는 3.22.0을 현재 버전으로 표기하므로 상충, 관리 상태는 `[미확인]`): [It's FOSS](https://itsfoss.com/image-viewers-linux.md)
- 휠 기본값 등 조작 세부는 확인 못 함 `[미확인]`.

#### Windows 사진 보기(구, Windows Photo Viewer)

- 복원하는 이유: "사진 앱보다 빠르고 단순하며, 창을 아주 작게부터 전체까지 조절할 수 있고 사진 자체만 보여 준다." 사진 앱은 사진 둘레에 큰 여백이 생긴다: [검색 요약(Winaero·Digital Citizen 등)](https://www.digitalcitizen.life/photo-viewer-for-windows-11-how-to-use-and-restore-it/) `[2차]`
- 사진 앱의 느린 실행: UWP에서 Windows App SDK로 옮긴 뒤 "Getting things ready" 화면이 약 20초 보였다는 관찰. MS도 느린 실행을 인정하고 백그라운드 상주로 완화하려 함: [Windows Latest](https://www.windowslatest.com/2024/06/05/windows-11s-photos-app-now-uses-more-web-tech-but-opens-slowly/), [한국 ITWorld](https://www.itworld.co.kr/article/3603292/pc-%EC%86%8D%EB%8F%84-%EC%A0%80%ED%95%98%EC%8B%9C%ED%82%A4%EB%8A%94-%EC%9C%88%EB%8F%84%EC%9A%B0-%EC%82%AC%EC%A7%84-%EC%95%B1%EC%9E%90%EB%8F%99-%EC%8B%A4%ED%96%89-%EB%A7%89%EB%8A%94.html) `[2차]`
- 표시 규칙: 작은 사진은 실제 크기, 큰 사진은 화면에 맞춤, 폴더 끝에서 처음으로 순환: [Wikipedia](https://en.wikipedia.org/wiki/Windows_Photo_Viewer) `[확인]`
- 휠: 구 뷰어의 휠은 확대(2010 MS 답변). 사진 앱에서는 이전·다음과 확대 중 선택: [MS Q&A](https://learn.microsoft.com/en-us/answers/a/4221015) `[확인]`. 한국어 글도 "윈도우 7 뷰어에 익숙한 사람은 휠로 확대하려다 사진이 넘어가 불편해한다"고 적음: [extrememanual](https://extrememanual.net/12753) `[확인]`
- 한계: 한 글만이 아니라 대부분이 속도 주장이 사용자 체감이며 MS 공식 벤치마크는 없음.

#### Picasa 사진 뷰어

- 직접적인 "그리운 이유" 글은 찾지 못했다 `[미확인]`. 단편 정보만 확인했다.
- 더블클릭하면 폴더 위에 반투명 배경으로 바로 사진이 뜸, Space로 배경 전환, 좌우·J/K로 이동, 휠 = 확대(설정으로 Ctrl = 이동), 1 = 100%, 8 = 별표, 에디터에서 한 편집이 뷰어에도 즉시 반영: [단축키 정리](https://www.sites.google.com/site/picasaresources/picasa/keyboard-shortcuts), [Wikipedia](https://en.wikipedia.org/wiki/Picasa) `[확인]`
- 대체재 설명에서 반복되는 요소는 "반투명 전체화면 배경", "클릭 가능한 썸네일 줄", "시작이 빠르고 다음 사진이 지연 없음": [Fly Photos](https://www.majorgeeks.com/files/details/fly_photos.html), [Reddit r/Windows10 2025-04 스레드(검색 요약)](https://reddit.birdcat.cafe/r/Windows10/comments/1jp4g3b/windows_photos_alternative) `[2차]`. 같은 스레드에 "꿀뷰가 Win7 뷰어와 비슷하다"는 댓글이 있음.

#### JPEGView

- 공식 readme(2017 개정): [readme.html](https://raw.githubusercontent.com/sylikc/jpegview/master/src/JPEGView/Config/readme.html) `[확인]`
- "화면에는 사진 외에 아무것도 보이지 않음", 기본이 전체화면(F11로 창 전환), 마우스를 화면 아래로 가져가면 조작 패널, 위로 가져가면 최소화·닫기.
- 휠 = 확대, 왼쪽 드래그 = 이동, PgUp·PgDn 또는 마우스 뒤로·앞으로 버튼 = 이전·다음, ESC = 종료, 우클릭 = 메뉴. 휠과 측면 버튼이 있는 마우스를 권장한다고 명시.
- 하단 패널에 "사진을 바꿔도 확대·이동 유지" 토글이 있음. 사진별 보정값을 별도 DB에 저장(원본은 그대로).
- 사용자 평: "다음 사진이 거의 즉시 뜬다": [SnapFiles](https://www.snapfiles.com/userreviews/113212/jpegview.html) `[2차]`

#### qimgv

- 소개·기본 조작: [GitHub](https://github.com/easymodo/qimgv) `[확인]`
- 철학: "UI 요소는 필요할 때만 보인다". 위에서 내려오는 썸네일 패널과 폴더 보기.
- 사진 정리: C(복사) 또는 M(이동)을 누르면 9개 폴더 패널이 열리고 숫자 키로 현재 사진을 보냄. 다시 누르면 닫힘. 폴더 아이콘을 눌러 목적지를 바꿈.
- 평가: AlternativeTo 평균 4.7점(13건), "이미지와 영상이 섞인 폴더 탐색에 적합": [검색 요약](https://www.centron.de/en/tutorial/three-of-the-besti-image-viewers-for-linux-ristretto-qimgv-and-nomacs/) `[2차]`. 반대 의견은 "기본 뷰어 이상은 아니다"(Manjaro 포럼). 개발이 정체됐을 수 있다는 지적 `[2차]`.

## 3. 꿀뷰가 "가장 편하다"는 평판을 얻은 요인

한국 글에서 직접 확인한 근거와, 공식 조작 체계에서 추정한 요인을 구분한다.

| 요인 | 근거 | 확인 수준 |
|:---|:---|:---|
| 가볍고 단순한 화면, 윈도우 기본 뷰어의 버벅임 대비 | 클리앙 [꿀뷰 소개 글](https://www.clien.net/service/board/lecture/18749175)의 "기능이 단순해 가볍다", 윈도우 기본 뷰어에서 버벅인 사람의 만족도가 높다는 서술 | `[확인]` |
| 즉시 열림·빠른 넘김 | 한국 후기 다수가 "빠르고 가볍다"(공식 소개도 "빠르고 가볍습니다"), 단 "다운로드 폴더에 사진이 많으면 실행 후 10초 넘게 로딩"이라는 반례: [루리웹](https://bbs.ruliweb.com/community/board/300143/read/66868514) | `[확인]`, 수치는 없음 |
| 압축 파일을 폴더처럼 열고 `]`·`[`로 다음 압축 파일로 이동 | [공식 소개](https://kr.bandisoft.com/honeyview/), [공식 단축키](https://en.bandisoft.com/honeyview/help/shortcut/). 나무위키 요약도 "주 용도는 압축 파일 속 이미지 열람" | `[확인]` |
| 만화 보기: 꽉차게 보기, 스마트 두 장 보기, 좌우 방향 전환(일본식 오른쪽→왼쪽, 한국식 왼쪽→오른쪽) | 클리앙 소개 글 | `[확인]` |
| 한 손 마우스 조작이 완결됨: 휠로 넘기기, Ctrl+휠로 확대, 더블클릭 최대화, 가운데 클릭 전체화면, Ctrl+가운데 클릭 100% | 공식 단축키 목록 | `[확인]`. "이래서 편하다"는 한국 사용자 직접 증언은 찾지 못함 `[미확인]` |
| 키보드로도 거의 모든 일을 함: 숫자 9·8·0 맞춤·너비·100%, 방향키·Space 이동, `Insert`로 즐겨찾는 폴더 복사 | 공식 단축키 목록 | `[확인]` |
| 창이 사진 크기를 따라가거나 고정되는 선택권 | 에토랜드 질답 | `[확인]`. 기본값과 체감 평가는 `[미확인]` |
| 설정을 건드리지 않아도 한글 UI, 개인·기업 무료, 광고 없음(꿀뷰 기준) | 나무위키 요약, 반디뷰 무료판 광고에 대한 클리앙 불만 | `[2차]` |
| 파일 관리 기능이 없는 "보기 집중" 도구 | 나무위키 요약, omdroid 비교 글 | `[2차]` |

한국 사용자 불만과 한계
- 업데이트 종료. 후속인 반디뷰는 "CPU 사용이 많고 로딩이 느리며 광고가 뜬다", "잔버그가 있다"는 이유로 꿀뷰로 돌아간 사람이 있음: [클리앙 1](https://www.clien.net/service/board/lecture/18749175), [클리앙 2](https://www.clien.net/service/board/park/19084497), [루리웹](https://bbs.ruliweb.com/community/board/300143/read/66868514). 반대로 반디뷰가 "굉장히 좋다"는 의견도 있음.
- 폴더 정렬: 윈도우 탐색기의 정렬 순서를 따르지 않고 파일명 순서로만 읽는다는 지적(나무위키 요약) `[2차]`.
- 확대·축소가 느리고, 상하 스크롤 시 사진이 넘어가는 현상을 호소하는 글이 반디캠 게시판에 있음(제목만 확인, 본문 403): [반디캠 게시판](https://www.bandicam.co.kr/board/honeyview/12058) `[미확인]`.
- 슬라이드쇼가 약함, 최신 포맷(AVIF·JXL) 미지원, 대형 파노라마에서 한계 `[2차]`: [FoxCG 비교](https://foxcg.com/honeyview-vs-bandiview/).
- 창 크기 단축키 없음(개발사 답변).

## 4. 맥 사용자 관점에서 참고할 한국어 언급

## 5. 반복해서 나타난 UX 패턴과 설계 시사점

| 패턴 | 나타난 앱 | 시사점 |
|:---|:---|:---|
| 사진이 화면의 거의 전부, 컨트롤은 가장자리에서 필요할 때만 등장 | JPEGView, FastStone, qimgv, Picasa | 기본 화면에 상시 툴바를 두지 않고 하단·상단 가장자리 호버 패널을 쓴다 |
| 휠 한 가지 역할 + Ctrl+휠 반대 역할, 설정으로 교체 | 꿀뷰, qimgv, Photos, Picasa, Gwenview | 기본값을 정하고(이전·다음 또는 확대) 반대 동작을 Ctrl 조합에 두며 설정에서 바꾸게 한다 |
| 클릭·더블클릭·가운데 클릭에 일관된 의미 | 꿀뷰, FastStone, JPEGView | 더블클릭 최대화, 가운데 클릭 전체화면, 클릭 한 번으로 맞춤↔100% 같은 규칙 |
| 사진이 바뀔 때 창이 널뛰지 않게 하는 선택권 | 꿀뷰(옵션), IrfanView(창 위치 기억), JPEGView(창 크기를 바꿔도 자동 맞춤 없음), 사진 앱 불만 | 창 크기 고정을 기본으로 두고, 사진에 맞추는 모드는 선택지로 둔다 |
| "맞춤 모드"가 이름 붙은 몇 개로 정리되고 숫자 키 하나로 호출 | 꿀뷰(9·8·0), qimgv(1·2·3, Space 순환), ImageGlass(여섯 모드) | 창 맞춤·너비·100%를 한 키로 오가게 하고, 작은 사진을 키울지 별도 토글로 둔다 |
| 확대 비율·위치 유지 여부를 명시적으로 토글 | 꿀뷰(Ctrl+K), JPEGView(하단 토글), FastStone(Ctrl+Shift+L), ImageGlass(잠금 모드) | 사진을 넘길 때 확대를 초기화할지 사용자가 선택 가능해야 한다 |
| 다음 사진이 지연 없이 뜸(미리 읽기) | ImageGlass(Turbo, 캐시), Fly Photos, JPEGView 평 | 앞뒤 사진을 미리 디코딩하고, 넘기는 동안 입력을 막지 않는다 |
| 폴더와 압축 파일을 같은 "순서 있는 묶음"으로 취급, 다음 묶음으로 이동 키 | 꿀뷰(`]` `[`), FastStone(다음 폴더 자동 이동) | 폴더 끝에서 다음 폴더로 넘어갈지 순환할지 정책을 정한다(Windows 구 뷰어·ImageGlass는 순환) |
| 정렬은 탐색기와 같게 | ImageGlass, Fly Photos가 강조, 꿀뷰의 파일명 고정은 불만 | Finder 정렬 순서를 따르는 편이 기대에 부합한다 |
| 빠른 복사·이동 대상 폴더를 숫자 키로 | qimgv(1~9 패널), FastStone(1~9), 꿀뷰(사진 폴더 1·2) | 보기 전용이어도 "보낼 폴더 몇 곳"만 두면 선별 흐름이 완성된다 |
| 별점·태그는 FastStone 계열의 선택 기능 | FastStone(Q, 1~5), IrfanView(X), Picasa(별) | 선별 기능은 별도 모드로 분리하고 기본 화면에는 노출하지 않는다 |
| 광고·알림·권유가 불만의 상위 | 알씨, 반디뷰 무료판, FastStone 시작 팝업 | 첫 실행·종료 시 팝업, 업데이트 알림을 두지 않는다 |
| 맥 사용자 추가 기대 | 제스처 줌, Space로 열고 닫기(Quick Look), 폴더 트리·썸네일 | 트랙패드 핀치 줌과 Quick Look식 즉시 닫기를 고려한다 |

## 6. 확인하지 못한 항목 목록

- 꿀뷰: "이미지 크기에 맞춰 창 크기 조절" 기본값, 휠 동작을 환경설정에서 바꾸는 방법, 한국 사용자가 직접 쓴 "휠이 편하다"류 증언
- 알씨: 휠·창·확대 동작 전부
- ImageGlass: 휠 기본값, 클릭 기본 매핑
- IrfanView: 휠 기본값, 확대 기억
- nomacs: 조작 기본값 전반, 유지보수 상태
- Picasa 사진 뷰어: 사용자가 그리워하는 이유를 직접 서술한 글(영어·한국어 모두)
- 2024~2026년 "최고의 UX"로 반복 거론된 새 뷰어: PicView(창이 사진 해상도에 맞춰 조절됨·UI 숨기기·G로 갤러리, 5.x에서 탭·도킹 갤러리가 추가됐다는 2차 정보), Fly Photos 정도만 확인했고 별도 비교 리뷰는 못 찾음
- Reddit 2025년 스레드 원문(다수 접근 불가), 뽐뿌·디시·네이버 블로그 본문
- 모든 응답 속도 서술은 사용자 체감이며 측정값을 찾지 못함
