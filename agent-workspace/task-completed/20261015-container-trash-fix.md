# 앱 데이터 폴더(Containers) 휴지통 이동 실패 수정

착수일: 2026-10-15
완료일: 2026-10-15
상태: 완료

## 증상

사용자가 앱 창에서 Paintbrush를 삭제 → 되돌리기 → 다시 삭제했을 때, 두 번의 삭제 모두 `~/Library/Containers/com.soggywaffles.paintbrush` 이동이 실패하고 결과가 '일부 완료'로 끝났다.

## 원인

- 실행 기록의 실패 사유: Finder `-5000` "필요한 권한이 없기 때문에 작업을 완료할 수 없습니다"
- 두 번 모두 정확히 15.5초 뒤 실패. 사람의 응답 시간이 아니라 Finder 내부 대기 후 거부로 판단
- 폴더에는 잠금 플래그나 ACL이 없고 `containermanager` 확장 속성만 있음. 일반 프로세스에서는 이름 변경이 0.035초 만에 성공(즉시 원복). Finder의 스크립트 이동만 거부되는 것으로 확인
- 중간의 되돌리기는 정상: 첫 삭제에서 실제로 이동된 앱 본체 1개만 되돌린 것

## 조치

- `kernel/trash.js`: 홈 아래 항목은 `/usr/bin/trash -v` 로 직접 이동하고 출력에서 실제 휴지통 이름을 기록, 되돌리기는 휴지통의 정확한 경로에서 직접 이동(원래 자리에 같은 이름이 있으면 덮어쓰지 않고 실패). 앱 본체는 관리자 암호 처리를 위해 Finder 우선. 각 경로가 거부되면 다른 경로로 재시도
- `apps.uninstall` 결과 카드에 이동하지 못한 항목의 경로를 표시
- README 휴지통 설명 갱신
- JXA(NSFileManager) 방식은 호출 즉시 강제 종료(137)되어 채택하지 않음

## 검증 (CLI, 이 세션의 프로세스 권한)

- Paintbrush 재현: 되돌리기 → 삭제(앱·데이터 폴더 모두 이동, 1초) → 되돌리기(2개 모두 원래 이름, 컨테이너 속성 유지) → 최종 삭제(사용자 의도 상태)
- 같은 이름 폴더 두 번 정리 후 각각 되돌리기: 내용 FIRST/SECOND 각각 정확히 복원
- 단위 시험 39건 통과, 개발 빌드 재설치

## 확인하지 못한 것

- 앱 창(Turink Toys 프로세스 권한)에서의 동작. 시험은 이 세션의 프로세스로 실행했으며, 앱에서 실행할 때 macOS가 '다른 앱의 데이터 접근' 허용을 물을 수 있다

## 정리

- 시험 중 처음 세션의 확인용 파일 하나가 휴지통에서 되살아나 시험 폴더와 함께 삭제했다
