# 이미지 뷰어 기능 추가

착수일: 2026-11-03
완료일: 2026-11-03

## 배경

- macOS 기본 이미지 뷰어(미리보기)와 지금 쓰는 앱(설치된 앱 기준 Pixea로 추정)이 불편하여 편집 없이 보기만 하는 뷰어를 추가함
- 기능과 기술은 일반적이므로 UX가 핵심(사용자, 11-03). 리서치부터 진행
- 사용자가 떠올린 기능 아이디어(UX 고려 전)
  - 목록: 폴더 탐색, 폴더 안 이미지 썸네일 목록, 고른 이미지를 따로 모아 관리하고 보기(사진 셀렉 도구의 기능, 필요 여부 미정)
  - 뷰어: 목록 화면의 큰 미리보기 창, 창 하나로 보는 뷰어, 창 크기·확대 비율·이미지 위치 조절

## 리서치 범위

- macOS 뷰어: 미리보기, 훑어보기(Quick Look), Pixea, Phiewer, ApolloOne, Xee³, Lyn, XnView MP, qView 등
- 다른 플랫폼에서 UX로 평가받는 뷰어: 꿀뷰(HoneyView), ImageGlass, FastStone, IrfanView 등
- 셀렉(컬링) 도구: Photo Mechanic, FastRawViewer, Lightroom, Narrative Select 등
- 공통 패턴: 열기 속도, 창 크기 자동 맞춤, 확대·이동, 키보드·트랙패드 조작, 목록과 뷰어 전환, 골라 두기 흐름, 사용자 불만

- 리서치 착수(서브에이전트 3개 병렬, 결과는 `20261103-image-viewer-data/` 에 보관)

- 결과 정리와 방향 제안: `20261103-image-viewer-data/ux-report.md` (원칙, 조작표, 결정 사항 5건)
- 시안: `20261103-image-viewer-data/mockup/index.html` (앱 스타일의 목록 화면과 뷰어 창, 가짜 사진·폴더, 휠·창 크기 옵션 전환 가능)
  - 확인: 열기, 맞춤·너비·100%, 커서 기준 확대, 확대 중 이동, 넘기기, 확대 비율 유지, 고르기·모아 보기·복사 창, 전체화면, 창 크기 세 가지 옵션 동작을 브라우저에서 점검
- 사용자 1차 검토 반영(11-03)
  - 저장한 폴더 제거, Finder 폴더 우클릭으로 여는 진입 추가(방식은 빠른 동작과 Finder 확장 중 결정 필요, 보고서 3절)
  - 문구 교정: 고른 사진 → 선택한 사진, 고르기 → 이 사진 선택, 모아보기 제목 「선택한 사진 모아보기 (n장)」, 뷰어 창 옵션 이름과 설명
  - 선택한 사진에 폴더로 이동 추가
  - UX 재검수 8건 반영(보고서 4절): 폴더 이름 중복, 전환 버튼 중복, 하위 폴더 키보드 선택, Space 닫기, 옵션 설명, 하단 막대 위치, 빈 모아보기, 복사·이동
- 결정(11-03): Finder 진입은 빠른 동작으로 하고 Finder 확장(Xcode 필요)은 쓰지 않음. 기존 빠른 동작과 Image Viewer 모두 이름에 `Turink-Toys` 접두어를 붙임(구현 때 설치 스크립트에서 이전 이름도 정리)
- 결정(11-03): 1~5 권장안대로 확정(휠 넘기기·⌘+휠 확대, 뷰어 창은 열 때만 맞춤, 사진 선택 포함, ⌘⌫ 휴지통, 기본 앱 지정). 보고서 5절
- 맥북 트랙패드 조작 설계·시안 반영(보고서 2절 「맥북 트랙패드」): 맞춘 상태의 위아래 스크롤 무시, 좌우 쓸기 한 번에 한 장(관성 무시), 확대 중 두 손가락 이동, 오므리기 확대, 목록 화면 오므리기로 썸네일 크기
  - 트랙패드와 마우스 휠 구분은 움직임 모양으로 판정. 시안의 「감지된 입력」 표시로 실제 맥북에서 확인 필요
  - 모의 입력으로 점검: 위아래 스크롤 무시, 관성 포함 쓸기 1장, 오므리기 확대, 확대 중 이동, 휠 한 칸 1장, ⌘+휠 확대
- 사용자가 맥북 트랙패드로 시안 확인(11-03), 설계 착수
- 설계: `20261103-image-viewer-data/design.md`(구조·태스크·화면·진입 경로·구현 단계·위험), `20261103-image-viewer-data/design-detail.md`(태스크 명세, IPC, 파일, 시험)
  - 코어 `images.*` 7개(list, selected, select, copy, move, trash, restore), 선택 목록은 코어 설정에 저장
  - 앱: 이미지 화면(앱 창), 재사용하는 뷰어 창 하나, 사진 전달용 전용 스킴, 화면 전환 없는 전체화면
  - HEIC·TIFF·RAW는 macOS 썸네일 기능과 sips 변환. 구현 2단계 첫 작업으로 실제 파일 확인
  - 자체 검수로 3건 수정: 새 오류 코드 등록, 읽기 태스크가 저장 목록을 고치지 않게 함, HEIC 변환 경로 교체
- 사용자 승인으로 구현 착수(11-03). 메뉴 막대(상단 시스템 메뉴)에는 이미지 뷰어 항목을 넣지 않기로 함(사용자)
- 구현
  - 코어(서브에이전트): `packages/core/src/tasks/images/` 태스크 7개와 formats·store·files, 오류 코드 `NOT_A_FOLDER`·`NOT_AN_IMAGE`, 한국어 태스크 문구, `test/images.test.js`
    - 명세와 다른 점: `images.trash` 결과 항목은 `{ from, trashName, bytes }`(기존 복원 도우미와 같은 형태), 복사·이동은 실행 전에 모든 경로를 검사해 하나라도 틀리면 전체 실패, 같은 폴더로 이동은 아무 일도 하지 않음
  - 앱 메인: `images.js`(사진·썸네일 전용 스킴, sips 변환과 qlmanage 썸네일, 캐시 500MB), `viewer-window.js`(창 하나 재사용, 크기 방식 3가지, 창 버튼 숨김, 화면 전환 없는 전체화면), `main.js`(Finder 열기 분배, IPC, 폴더 감시), `preload.js`
  - 렌더러: `screens/images.js`(이미지 화면), `viewer.html`·`viewer.js`, `viewer-math.js`·`wheel-input.js`(시험 가능한 모듈), 아이콘·문구(영어·한국어)·스타일
  - 연동: `scripts/bundle-app.js` 이미지 형식 등록(대체 앱 등급), `integrations/quick-actions/install.js` 접두어 `Turink-Toys`와 Image Viewer 동작, README
  - 변환 경로 확인으로 설계 수정: Electron의 `nativeImage` 는 HEIC·TIFF를 못 읽고 썸네일 비율이 틀려 sips와 qlmanage로 교체
- 확인
  - 테스트 110건 통과(코어 images 25건, 확대 계산·트랙패드 판정 12건 추가)
  - 소스 실행: 이미지 화면(폴더·HEIC·TIFF·PNG 썸네일, 사진 아닌 파일 제외, 미리보기 크기 표시), 뷰어(HEIC 4000×2000 표시, 창 크기 맞춤, 100%, 넘기기, 선택, 위쪽 가장자리 정보 막대)
  - 개발용 앱 재설치 후 `open -b`(빠른 동작과 같은 명령): 사진을 열면 뷰어 창만, 폴더를 열면 앱 창이 이미지 화면으로 열림
  - 빠른 동작 4개 설치, 예전 이름 정리 확인
  - 확인 중 고친 것: 긴 경로에서 현재 폴더가 잘림 → 앞부분 줄임, 숨긴 선택 막대가 보임, 코어 테스트의 배열 비교 오류
  - 직접 확인하지 못함: Finder 우클릭 메뉴 화면(접근성 권한 없음), 실제 트랙패드 조작, RAW 파일(샘플 없음), 다른 볼륨으로의 이동
- 사용자 확인에서 발견(11-03): 키보드 P가 반응하지 않음. 한글 입력 상태에서는 P 키가 「ㅔ」로 들어와 문자 비교가 실패한 것. 뷰어와 이미지 화면의 문자 단축키(P, L, F, ⌘Z)를 키 위치(`e.code`)로 판별하도록 수정, 개발용 앱 재설치 후 한글 키 값으로 확인
- 사용자 확인에서 발견(11-03): 뷰어 위쪽 막대가 나타날 때 심하게 깜박이고 버벅임
  - 원인 ①: 막대가 창 끌기 영역이라 마우스가 올라가면 macOS가 포인터를 가져가고 페이지에는 「벗어남」이 전달됨 → 막대 숨김 → 다시 표시가 반복됨. 수정: 막대 위에서 온 벗어남은 무시, 나타남(52px)과 사라짐(80px) 경계를 달리 둠, 창이 비활성화되면 숨김
  - 원인 ②: 막대 뒤 흐림 효과(backdrop-filter)가 큰 사진 위에서 매 프레임 계산됨. 수정: 반투명 배경으로 교체
  - 확인: 브라우저 수준 마우스 입력으로 막대 위 벗어남 시 유지, 경계 떨림 시 유지, 확실히 벗어나면 숨김. 개발용 앱 재설치
- 사용자 확인에서 발견(11-03): 뷰어 창 신호등 버튼이 위쪽 막대 가운데보다 약 6pt 위에 있음(사용자 스크린샷에서 측정: 막대 가운데 22pt, 버튼 가운데 약 16pt). `trafficLightPosition` 을 `{ x: 16, y: 21 }` 로 바꿔 재설치. 창 버튼은 화면 캡처에 잡히지 않아 사용자 확인 필요
- 신호등 버튼 재수정(11-03): 위치값을 바꿔도 그대로였던 원인은 창 버튼을 숨겼다 다시 보이면 macOS가 기본 위치로 되돌리는 것. 보일 때마다 `setWindowButtonPosition` 으로 다시 지정하고 값은 원래 의도대로 `{ x: 16, y: 15 }`. 화면 캡처로 확인: 버튼 가운데 21.5px, 제목 글자 가운데 약 22px
- 사용자 확인(11-03) 후 완료 처리. 연관 문서의 경로는 `20261103-image-viewer-data/` 로 옮김
