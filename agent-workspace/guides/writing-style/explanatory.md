# 설명문 작성 가이드

이 가이드는 사용자의 명시적 요청이 있을 때만 적용하며 에이전트가 임의로 판단하여 적용하지 않는다.

독자에게 어떤 영역을 이해시키는 문서에 적용한다. 해설서, 입문서, 개념 안내서, 작업 매뉴얼, 교육 교재가 대상이다. 값을 찾으려고 여는 문서(인터페이스 명세, 규격서, 변경 이력)와 합의를 위한 문서(설계 문서, 제안서, 보고서, 회의록)는 대상이 아니다. 한 문서가 두 목적을 겸하면 부분마다 판정한다.

이 가이드에서 「자료」는 사용자가 제공한 문서와 작성자가 출처를 밝혀 확인한 원천 자료(법령, 고시, 공식 규격, 제품 공식 문서, 코드)를 뜻한다. 이 가이드의 수치 기준(문장 길이, 절 수, 셀 길이, 도식 요소 수, 용어 수)은 운용 기준이며 근거가 생기면 바꾼다.

## 1. 근거와 자료

- 자료에 있는 것만 쓴다. 배경지식으로 안다고 생각되는 것도 자료에 없으면 쓰지 않는다. 법률명, 기관명, 영문 원어, 연도, 계산식이 여기 해당한다
- 근거가 없는 문장은 빼거나 확인하지 못했다는 사실을 본문 문장으로 적는다. 예: 「신청부터 승인까지의 실제 소요 기간은 확인하지 못했다」
- 자료가 「확인하지 못했다」, 「자료마다 다르다」, 「추정된다」로 유보한 것은 유보 그대로 옮긴다
- 한 사례로만 확인한 것은 「한 기관의 사례에서는」처럼 확인된 범위로 한정해 적는다
- 인용 부호로 감싼 문장, 인용 블록, 문장 끝에 조항 근거를 괄호로 붙인 문장은 원문이다. 조사 하나도 바꾸지 않는다
- 인용 블록은 규범과 원자료의 원문에만 쓰고 판단에 직접 쓰이는 문장만 발췌한다. 출처 줄은 「출처: 문서명(판본 또는 고시 번호, 발행 연월), 조항 또는 쪽」 형식이다
- 본문 문장에 근거를 붙일 때는 문장 끝 괄호에 조항이나 출처를 적는다. 근거는 자료가 특정한 만큼만 적는다. 조 번호까지만 밝힌 자료에 항이나 호를 추정해 붙이지 않는다
- 한 절이 여러 조항에 걸치면 문장마다 괄호를 붙이지 않고 항목과 근거 두 열의 근거표로 모은다
- 다 쓴 뒤에는 산출물과 자료를 나란히 놓고 대조한다. 대상은 수치, 날짜, 기한, 조항 번호, 기관명·법령명·규격명, 유보한 사항, 한정 표현, 요건의 조건이다

## 2. 독자와 문서 골격

- 독자는 그 영역의 사전지식이 없다. 독자가 이미 안다고 전제하는 문장(「아시다시피」, 「기본 개념은 생략한다」, 「앞서 다룬 기준을 떠올리면」)을 쓰지 않는다. 필요한 내용은 그 자리에서 한 문장으로 다시 적는다
- 한 장은 파일 하나다. 단일 파일로 완결되는 설명문은 문서 전체를 한 장으로 보아 구성한다
- 장은 제목, 첫 문단, 번호를 붙인 본문 절 3~6개로 구성한다. 계층은 장, 절, 항까지만 쓴다
- 장·절·항 제목은 다루는 대상을 특정하는 명사구다. 질문형이나 서술문 제목을 쓰지 않는다
- 첫 문단은 대상이 무엇이고 왜 있는지를 두세 문장으로 적는다. 시점에 따라 달라지는 정보를 다루면 근거와 기준 시점을 적은 문장 하나를 끝에 더한다. 예: 「국내 절차의 근거는 ~이며 2026년 9월 기준이다」
- 장을 「이 장은 ~를 다룬다」처럼 문서가 자기 얘기를 하는 문장으로 시작하지 않는다. 「개요」 제목을 붙이지 않는다
- 절 사이에 순서나 의존 관계가 있으면 장 제목 바로 아래에 구조 도식을 둔다. 노드는 절과 하나씩 대응하고 7개 이하다. 절이 나열이나 분류이면 그리지 않는다
- 도입 경위, 연혁, 시장 동향 같은 배경은 배경 장 하나에 모은다. 단일 파일이면 본문 앞부분의 배경 절 하나에 모은다. 개념과 절차를 설명하는 절에는 배경을 섞지 않는다

## 3. 절 안의 설명 순서

절 안은 개념, 근거, 절차, 예시, 대응, 주의 순서로 쓴다. 해당 내용이 없는 부분은 생략하고 순서는 바꾸지 않는다. 각 부분의 규칙과 이유·예외·비교를 쓰는 방법은 다음과 같다.

- 개념: 정의는 한 문장으로 끝낸다. 형식은 「표제어는 상위 범주다」에 같은 범주의 다른 대상과 갈리는 조건과 경계를 붙이는 것이다. 순환 정의, 평가어 정의(「매우 중요한 개념이다」), 법령 문체(「~라 함은 ~을 말한다」)를 쓰지 않는다
- 이유: 규칙을 첫 문장에 쓰고 그 규칙이 해결하는 문제를 같은 문단 둘째 문장부터 쓴다. 이유를 확인하지 못했으면 추정하지 않고 생략한다
- 절차: 주체와 조건을 문장 앞에 두고 동작을 뒤에 둔다. 한 문장에 한 동작만 담는다. 단계가 셋 이상이면 단계·수행 주체·산출물 세 열의 단계표나 번호 목록으로 쓴다
- 예시: 숫자나 날짜 같은 구체적인 값을 넣는다. 예시는 「예를 들어」로 시작하는 본문 문단으로 쓰고 코드와 명령 예시는 코드 블록으로 쓴다. 자료에 반례가 있으면 예시와 핵심 조건 하나만 다른 것을 골라 붙이고 없으면 예시만 둔다. 예시와 반례는 지어내지 않는다
- 예외: 기본 규칙을 먼저 확정하고 예외는 문단을 바꾸어 뒤에 둔다. 기본 규칙 문장 안에 괄호나 「다만」으로 예외를 끼워 넣지 않는다
- 대응: 두 체계를 함께 다루면 먼저 서술한 체계의 요소에 다른 체계를 대응시켜 뒤에 붙인다
- 비교: 결론을 「A와 B는 무엇이 다르다」 한 문장으로 먼저 적고 비교표로 대조한다. 우열을 판정하지 않고 차이만 적는다
- 주의: 금지 사항을 부정형 단문으로 적고 어긋났을 때의 결과나 대안을 붙인다. 강조 부사로 강도를 올리지 않고 결과를 적는다. 경고 상자는 되돌릴 수 없는 결과를 알릴 때만 쓰고 그 밖의 주의는 본문 문단으로 쓴다

## 4. 문장

- 한 문장에 조건이나 정보를 하나씩 담는다. 100자를 넘으면 나눈다
- 문장 안에서 「및」을 쓰지 않는다. 나열은 「와/과」나 가운뎃점으로 한다. 법령명·고시명·서식명 안의 「및」은 원문이므로 그대로 둔다
- 연결어미 뒤에 콤마를 붙이지 않는다. 나열 항목을 구분할 때만 콤마를 쓴다
- 번역투(「~에 대하여」, 「~을 통해」, 「~되어지다」, 「~에 있어서」, 「~로부터」)는 인용문이 아니면 쓰지 않는다
- 굵은 글씨는 용어를 처음 정의하는 자리의 표제어에만 쓴다
- 반드시, 절대, 결코, 명확히, 정확히, 엄격히, 완전히, 빠짐없이, 면밀히를 강조로 쓰지 않는다. 「값이 정확히 일치한다」처럼 사실을 서술하는 쓰임은 해당하지 않는다

## 5. 용어

- 용어는 처음 나오는 문장 옆에서 한 문장으로 정의한다. 같은 파일 안에서는 두 번째 등장부터 정의를 되풀이하지 않는다
- 절마다 처음 도입하는 용어는 다섯 개 이하로 한다. 넘으면 절을 나눈다
- 한 대상은 한 명칭으로만 부른다
- 표기는 규범, 표준, 공인 자료가 쓰는 표기를 확인해 채택한다. 정착된 국문 명칭이 없는 고유 명칭은 본문과 라벨 모두 원어로 적는다. 외래어 음차로 새 명칭을 만들거나 자체 조어를 쓰지 않는다
- 원어 병기는 약어와 고유 명칭에만 한다. 형식은 「국문(원어, 약어)」이고 파일마다 첫 등장 1회만 병기한다. 자료에서 원어를 확인하지 못하면 병기하지 않는다

## 6. 표

- 표는 같은 기준을 여러 대상에 적용해 대조할 때와 한 행에서 여러 속성을 함께 읽어야 할 때 쓴다. 대상이 둘이고 속성이 하나면 문장으로 쓰고 셀에 이유와 배경이 들어가면 문단으로 쓴다
- 표 앞에는 「다음과 같다」로 끝나는 도입 문장을 둔다. 행 개수를 적지 않는다
- 분류·속성·대상·산출물을 담는 열은 명사형으로 끝내고 정의·설명·비고·이유를 담는 열은 서술문으로 끝낸다. 한 열 안에서 두 형식을 섞지 않는다
- 셀의 마지막 마침표는 생략한다. 한 셀이 40자를 넘으면 본문 문단으로 옮긴다. 값이 없는 칸은 「해당 없음」으로 채운다
- 비교표의 첫 열은 비교 기준이다. 셀에 우열을 뜻하는 말을 적지 않는다. 조건이 붙은 항목은 조건까지 적는다
- 용어표는 용어, 원어·약어, 정의, 출처 네 열이며 용어의 가나다 순으로 정렬한다

## 7. 도식

- flowchart, sequenceDiagram, stateDiagram-v2 셋을 기본으로 쓴다. 이 셋으로 나타낼 수 없는 정보(데이터 구조 등)일 때만 다른 유형을 쓴다. 도식은 텍스트 기반으로 쓰고 이미지 파일로 넣지 않는다
- 도식은 요소를 잇는 선에 「다음 단계」, 「승인 시」, 「포함」 같은 이름을 붙일 수 있을 때만 그린다. 나열, 분류, 목차, 속성 대조, 연표, 계산은 문장이나 표로 쓴다
- 도식 하나의 노드는 그룹 안 노드를 포함해 15개 이하이고 그룹으로 묶지 않은 노드와 그룹 상자의 합은 9개 이하다. 넘으면 묶거나 나눈다
- 노드 라벨은 노드 안에 직접 적는다. A, B 같은 기호를 두고 도식 밖에서 뜻을 설명하지 않는다
- 라벨은 한 행 12자 이내의 국문 명사구다. 부연은 둘째 행에 괄호로 적고 첫째 행에는 괄호를 쓰지 않는다
- 색만으로 구분하지 않고 도형도 함께 구분한다. 선 종류나 스타일을 둘 이상 쓰면 도식 바로 아래에 범례 표를 둔다
- 리드문 한 문장, 도식, 도식이 담지 못한 조건과 예외를 적은 문단 순서로 배치한다. 도식이 보인 순서를 문장으로 되풀이하지 않는다
- 본문을 고치면 도식도 함께 고쳐 둘이 어긋나지 않게 한다

## 8. 산출물에 적지 않는 것

- 문서를 만든 사정은 산출물에 적지 않는다. 학습 목표(「이 장을 읽으면 ~를 알 수 있다」), 독자 규정, 범위를 그렇게 정한 이유가 여기 속한다. 자료를 고른 방법과 건수, 작업 지침, 진행 상태(「추후 보완 예정」), 작성 순서도 적지 않는다
- 작업용 표기를 괄호로 본문에 남기지 않는다
- 독자 모형, 주제별 담당 장, 해소하지 못한 항목의 확인 목록은 작업 계획이나 작업 메모에 둔다
