# 기술 문서 작성 가이드

사용자의 별도 요청이 없으면 이 가이드를 기본으로 적용한다. 프로젝트가 에이전트와 사용자에게 제공하는 안내 문서, 매뉴얼, API와 규격 문서에 적용한다. 문체는 공식 문체 글 작성 가이드(`official.md`)를 따르고 이 가이드는 구성과 표기를 정한다.

## 1. 절 구성

문서의 각 절은 핵심과 부가 설명을 분리하여 간결하게 구성한다.

- 절 제목: 다루는 대상을 특정하는 명사구 사용
- 목적 설명: 필요할 때만 한두 문장으로 기술
- 핵심 내용: 불릿으로 간단명료하게 기술
  - 사실 단위: 한 불릿에 사실 하나 배치
  - 계층 구조: 관련 하위 내용은 하위 불릿으로 Depth를 조절하며 3단계까지 구성
- 순서가 있는 항목: 번호 목록으로 기술
  - 하위 불릿: 번호 항목 아래 관련 내용은 불릿과 같이 Depth 3단계까지 구성
  - 부가 설명 문단: 번호 항목 아래 들여 써서 그 항목에 속하게 배치
- 부가 설명: 불릿 뒤에 문단으로 배치

핵심과 부가를 섞어 긴 문장으로 연결하지 않는다. 이유, 예외, 예처럼 부가적으로 설명할 필요가 있는 내용만 문단으로 작성한다.

## 2. 표

- 표 칸: 짧은 문장만 배치
- 긴 설명의 분리: 표 아래 본문(소제목과 불릿)으로 이동
  - 칸 안의 표기: 「아래 ○○ 참고」와 같이 안내
  - 분리 기준: 한 칸의 내용이 몇 문장을 넘을 때 적용
- 열 구성 준수: 호출·본문·설명처럼 열의 의미가 정해진 표는 해당 열 유지

## 3. 키·값과 식별자 표기

코드와 데이터 구조를 나타내는 요소는 정해진 표기 규칙을 준수한다.

- 코드 요소 표기: 키, 값, 코드, 경로는 백틱(`) 사용
- 허용 값 나열: 「a, b, c 가운데 하나」 형식 사용
- 부가 속성 표기: 선택 항목, 한도, 기본값은 괄호 안에 짧게 병기
  - 선택 항목과 한도: 「(선택, 200자까지)」
  - 기본값: 「(기본값 2)」
- 객체 모양: `{a, b, c}` 형태로 먼저 보이고 속성은 하위 불릿으로 하나씩 기술

예:
- `description`: `{field, lines}`(선택)
  - `field`: 대상 필드 이름
  - `lines`: 줄 수

## 4. 문장

에이전트나 사용자가 읽고 바로 행동할 수 있는 사실만 기술한다.

- 서술 내용: 에이전트나 사용자가 읽고 바로 행동할 수 있는 사실만 기술
- 서술 단위: 한 문장에 사실 하나 기술
- 종결 어미: 문서는 「~한다」로 종결
- 배경 서술 배제: 요청이나 지침의 배경, 결정 경위 서술 금지(`official.md` 3절)
- 표현 제약: 구어체와 주절주절 이어지는 문장 사용 금지

## 5. 한글본과 영문본

한글본과 영문본은 동일한 사실과 체계를 유지한다.

- 구조와 사실: 같은 구조와 같은 사실 유지
- 영문 문체: 직역하지 않고 그 문서의 영어 문체로 재작성
- 식별자 일치: 값 목록과 식별자는 똑같이 유지

## 6. 검수

문서를 작성한 뒤에는 다음 순서로 검수한다.

1. 원문 대조: 쓴 뒤 원문(바꾸기 전 글)과 대조해 빠진 사실이 없는지 점검
2. 지침 대조: `official.md`와 프로젝트 용어집(있는 경우)에 대조
3. 뜻 보존: 교정 시 뜻을 바꾸지 않음

## 7. 구성 예

```markdown
## 절 제목

절의 목적을 설명하는 한두 문장이다.

- 핵심 사실 하나
  - 하위 내용
- 핵심 사실 둘

1. 첫 단계
   - 첫 단계의 세부 내용
     - 하위 내용
2. 둘째 단계

   둘째 단계에만 해당하는 부가 설명 문단이다.

이유나 예외, 예와 같은 부가 설명 문단이다.
```
